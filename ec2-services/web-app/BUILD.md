# Web-app build & deploy cheat-sheet

> Vite → static HTML/JS/CSS → either nginx-in-Docker (preview) or S3 + CloudFront (prod).

## Source vs output

| What | Where | Mutable? |
|------|-------|----------|
| Source code | `src/` | yes (edit) |
| Build output | `dist/` | no (regenerated by build) |
| Local-dev server | `vite` (port 5173) | hot reload |
| Local nginx mode | `Dockerfile` (proxies APIs to service containers) | docker compose |
| Production image | `Dockerfile.prod` (calls `api.rajesh-project.com` directly) | static |

## Scripts

```bash
npm run dev              # vite dev server with HMR — http://localhost:5173
npm run build            # vite build (no mode) — outputs to dist/
npm run build:prod       # build with .env.production loaded
npm run build:staging    # build with .env.staging loaded
npm run preview          # serve dist/ locally on :5173 (smoke-test the prod bundle)
npm run deploy:s3        # sync dist/ → s3://$S3_BUCKET; needs AWS creds + S3_BUCKET env
npm run deploy:invalidate # CloudFront invalidation on $CF_DIST_ID
```

## Env-mode files

Vite picks the right env file from the `--mode` flag:

| Mode | File loaded |
|------|-------------|
| (default / dev) | `.env`, `.env.local` |
| `production` | `.env`, `.env.production`, `.env.local`, `.env.production.local` |
| `staging` | `.env`, `.env.staging`, `.env.local`, `.env.staging.local` |

`.env.example` is the template — copy to `.env.local` (gitignored) for personal overrides.

Only variables prefixed `VITE_` are exposed to the browser bundle. Everything else stays server-side.

## Three deploy paths

### A. Local docker-compose (current `Dockerfile`)

The local mode keeps nginx as a proxy in front of all service containers — every `/api/v1/*` route is forwarded inside the Docker network. Use this for `docker compose up`.

```bash
docker compose build web
docker compose up -d web
# → http://localhost:8080
```

### B. Production Docker image (`Dockerfile.prod`)

The prod build talks directly to `api.rajesh-project.com` — no in-container proxy. Suitable for any K8s / ECS deployment where the SPA pod sits next to the API gateway.

```bash
docker build -f Dockerfile.prod \
  --build-arg VITE_API_BASE=https://api.rajesh-project.com \
  --build-arg VITE_API_KEY=$ANONYMOUS_API_KEY \
  -t web-app:prod .

docker run -p 8080:8080 web-app:prod
# → http://localhost:8080 (uses real api.rajesh-project.com — needs network access)
```

### C. S3 + CloudFront (recommended for production)

No container at all — static files behind a CDN. Cheapest, fastest, simplest.

```bash
# 1. Build with prod env
VITE_API_BASE=https://api.rajesh-project.com \
VITE_API_KEY=$ANONYMOUS_API_KEY \
  npm run build:prod

# 2. Sync to S3 (hashed assets get immutable cache, index.html gets no-cache)
S3_BUCKET=ecommerce-rajesh-com-static npm run deploy:s3

# 3. Bust CloudFront's edge cache
CF_DIST_ID=E1ABCDEFG npm run deploy:invalidate
```

That's it. The build is 100% static — `index.html` plus content-hashed JS/CSS in `dist/assets/`.

## Where the files come from — the build chain

```
src/main.jsx (entry)
        │
        ▼
Vite (esbuild + Rollup)
        │
        ▼
dist/
├── index.html                ← entry HTML (NOT cached at the edge)
├── assets/
│   ├── index-DCa7d3.js       ← content-hashed; cached 1 year
│   ├── index-9f17ed.css      ← content-hashed; cached 1 year
│   ├── react-vendor-7a2b1.js ← split chunk for libraries
│   └── …png /.webp / fonts
└── locales/, leaflet/, …     ← public/ folder copies as-is
```

`vite.config.js` controls chunking, public path, and which env files are loaded. The nginx config (`nginx.prod.conf`) serves `dist/` with the right cache headers — long for hashed assets, no-cache for `index.html`.

## CI integration

The same npm scripts run in CI. Bitbucket pipelines is already wired in `bitbucket-pipelines.yml`; for GitHub Actions, mirror it:

```yaml
# .github/workflows/deploy.yml — sketch
- uses: actions/setup-node@v4
  with: { node-version: '20', cache: 'npm' }
- run: npm ci
- run: npm run build:prod
  env:
    VITE_API_BASE: ${{ secrets.VITE_API_BASE }}
    VITE_API_KEY: ${{ secrets.VITE_API_KEY }}
- run: npm run deploy:s3
  env:
    S3_BUCKET: ${{ secrets.S3_BUCKET }}
    AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
    AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
- run: npm run deploy:invalidate
  env:
    CF_DIST_ID: ${{ secrets.CF_DIST_ID }}
```

## Verifying a build

```bash
npm run build:prod
npm run preview              # smoke-test the bundle locally on :5173
# Open DevTools → Network → verify every /api call goes to api.rajesh-project.com
# Open DevTools → Application → verify no source maps leak (prod build strips them)
```

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `import.meta.env.VITE_API_BASE` is `undefined` in prod | Build was run without the right `--mode` | Use `npm run build:prod` (loads `.env.production`) |
| All requests go to the wrong domain | Build-time env was wrong; bundle is immutable | Re-run `build:prod` with the right `VITE_API_BASE`, redeploy |
| CloudFront serves an old `index.html` after deploy | Edge cache stale | Run `deploy:invalidate` |
| 403 from S3 directly when CloudFront is bypassed | Bucket is private (correct!) | Always go via CloudFront URL |
| 200 OK with empty page in iframe | CSP `frame-ancestors`/`X-Frame-Options DENY` blocks it | Intentional — relax in `nginx.prod.conf` only if you really need iframes |
